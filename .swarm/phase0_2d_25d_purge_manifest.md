## 0. HEADLINE FINDINGS (read first)

1. **There is NO live true-3D render path that is independent of a 2D swapper.** Every live mode calls a 2D neural swapper:
   - `standard` (default): `engine/volumetric/session.py:807` `self.swapper.infer_frame(...)` -> inswapper_128 on a 5-point aligned crop -> paste (`Replacement.inverse`).
   - `pose_3d`: same swap crop (`session.py:807`) then projected by `PoseBlendProjector` onto a 68-landmark Delaunay strip proxy (`session.py:840,963`).
   - `reenactment_3d`: swap crop is computed first (`session.py:807`), then `ReenactmentEngine` is cross-faded over it (`session.py:972-1008`).
   - Auto 3D (`auto_3d_limits`, yaw>30 / pitch>25, `session.py:1161`): `NeuralFaceEngine.process` (`reconstruction/neural_face.py:332`) builds a 3D correspondence
     "conditioning crop" but then feeds it to the 2D swapper (`neural_face.py:437` `swapper.synthesize_correspondence` -> `identity_swapper.py:312`) and runs UltraMax/CodeFormer on the
     2D crop (`neural_face.py:443`). The 3D geometry only conditions a 2D network.
   - `FullHeadEngine` / `GPUHeadRasterizer` (`reconstruction/full_head.py:269/70`) are the only true K[R|t] perspective + GPU z-buffer head renderer, but `FullHeadEngine` is NOT
     instantiated anywhere in live code (`session.py:192` only creates an empty dict; no `FullHeadEngine(` call outside tests). `GPUHeadRasterizer` is used only by
     `uv_synthesizer`, `photometric_gpu`, `gpu_background`, `physical_buffers`, `faceset_synthesizer`, `tools/prepare_relighting_case`.
   => Deleting the 2D swappers FIRST would leave the app unable to produce a swapped frame. The True-3D renderer (FullHeadEngine + PhysicalBufferRenderer + a new neural-PBR/Gaussian
   head layer) must be wired into `ReferencePipeline`/`Replacement` BEFORE the swapper stack is deleted. See section 6 (order) and 7 (risks).
2. **No neural restorer currently runs in UV space.** All CodeFormer / GFPGAN / GPEN / UltraMax usage is on aligned 2D frame/crop pixels AFTER the swap (`compositor/restoration.py`,
   `stream_restoration.py`, `neural_face.py:443`, `photorealistic_swap_core.py:551-618`) or on 2D generated portraits (`faceset_synthesizer.py:186-241`). The "KEEP UV-space-only" list for
   GAN detailers is therefore EMPTY today; what exists in UV space (`rendering/uv_baker.py`, `reconstruction/uv_completion.py`, `albedo_prior.py`, `intrinsic_texture.py`) is classical, not neural.
   The CodeFormer/GFPGAN/GPEN WEIGHTS may be reused later as offline UV-atlas builders, but no code path for that exists.
3. **Weak-perspective is pervasive, not an edge case.** `WeakPerspectiveCamera` (`reconstruction/geometry_types.py:435`) is the camera of the multiview identity fit, UV texture baking,
   reenactment, head tracker, lighting, scene adaptation and GLB export. Replacing it touches ~12 backend files plus their tests. A perspective alternative already exists
   (`CameraIntrinsics`, `solve_pose_pnp`, `solve_dense_pose`, `dynamic_camera.py`, `full_head.HeadPose`) so this is a REFACTOR, not a greenfield.
4. **The "full cranium" template exists but is not the default.** `identity_asset.py:68` default `template: "canonical"` = `build_canonical_head_mesh` (68 landmarks + 8 boundary points,
   Delaunay on the XY plane = frontal strip, `tps_fallback.py:274-335`). The MakeHuman CC0 head+neck (`makehuman_template.py`) is the existing full-head alternative but exposes 5-point landmarks only
   and "does not apply `subdivisions`" (`identity_asset.py:66-67`). Reenactment/pose_blend/flame_fitter/multiview_fit all assume the canonical 68-vertex layout (indices 0..67).
5. `swappers/` package (swapper_base/pixel_boost/hififace) is DEAD code (only `tests/test_model_registry.py` imports it). Safe first deletion.
6. `enhancers/` classes (`GPENRealisticRestorer`, `DynamicCodeFormerRestorer`, `RestoreFormerPlusPlusRestorer`, `UltraMaxRestorer`) are imported only by tests; the one ACTIVE piece is
   `enhancers/ultramax.py::laplacian_pyramid_fusion` + `to_model_input/from_model_output/require_session` (used by `compositor/restoration.py:232,256,282`). A generic Laplacian fuse is legitimate; extract it before deleting.

## 7. Replacement / fallback risks (what breaks)

1. **App cannot produce output after step 5 unless step 2 is done.** All live modes call `swapper.infer_frame` (`session.py:807`) or `synthesize_correspondence` (`neural_face.py:437`). That fallback target is exactly what is being deleted - those branches must be re-pointed or removed.
2. **Default job engine is the inswapper stream runner** (`server/app.py:98` `make_stream_runner`; `engine/registry.py` `reference_onnx`). Deleting `optimized_processor` removes the default engine; `photoreal_3d_ffmpeg` (`video_job_runner.py`) is the only other engine and also constructs a `ReferencePipeline` with a swapper. `GET /health` swap-engine summary (`engine_readiness.py`) will report zero engines ("READY" gating in UI `EngineStatusBar`). Preflight (`/api/v1/preflight*`) `diagnostics.py:502` requires a swapper id.
