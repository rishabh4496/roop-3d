# 01 Engine inventory - what exists today in `app/roop_3d/`

Scope: the ten Stage 14 categories (face detection, face recognition, dense landmarks, identity swapping, 3D reconstruction, expression transfer, occlusion segmentation, restoration, video decoding, video encoding). Vocabulary follows `docs/GLOSSARY.md` (Model, Engine, Pipeline plan, Render profile, Job runner). "Engine" is never used here for the job runner (`engine/registry.py:EngineRegistry`).

Conventions
- Paths are relative to `app/roop_3d/` (repo root `G:\pinokio\api\roop-3d`) unless prefixed. `file:line` cites the working tree read on 2026-11-04.
- "Wired" levels used in the tables: **J** = reachable from the job runners (reference `MasterPipelineRunner` or stream `StreamDispatchRunner`); **P** = reachable only from inspection/preview endpoints; **U** = adapter code exists but nothing under `server/`, `jobs/`, `engine/` or the two runners calls it (only tests, benchmarks, tools); **-** = no adapter code at all, or a stand-in that fabricates its output.
- Model ids are `ModelRecord.model_id` (24-hex for the preserved discovery manifest). Several ids can point at byte-identical files (same sha256, different locator); that is noted as "dup ids".

Method: read the files named in the ticket plus their callers (grep for every class and model filename across `app/roop_3d/**/*.py` excluding `.venv`, `.runtime`, `tests`). Executed (read-only, not pytest): import-only Python snippets with the checkout's `.venv` Python to load `ModelRegistry`, run `ModelCompatibilityScanner`, call `ModelCatalog.resolve_for_inference` / `LocalWeightProvider.resolve` (this hashes weight files), and summarize JSON. No repo file other than this one was written. `git status` after the runs shows only the two pre-existing untracked paths (`GLOSSARY.md`, `docs/wayfinder/`).

## 0. Cross-cutting facts that bind every category

**F1. The only registry named "engine" is the job-runner registry.** `engine/registry.py:9-13` defines `REFERENCE_ENGINE = "reference_onnx"` and `UNAVAILABLE_ENGINES` (`minimax_h3_ref2va_experimental`, `bfs_qwen_image21_experimental`, both refuse with `ENGINE_UNAVAILABLE`, 409). `register()` only accepts a runner with `prepare`, `run_prepared`, `retry_profile` (`:42-43`). The worker binds exactly one runner: `jobs/worker.py:37-38` (`bind_reference`). `jobs/schema.py:58` default `engine_id="reference_onnx"`. There is no per-capability Engine registry anywhere. `models/hub.py:254-321` hand-writes three "engine" dicts (reference_onnx, MiniMax, Qwen).

**F2. Two render backends choose the adapters.** `optimized_processor.py:204-334` (`make_stream_runner`, installed by `server/app.py:66-70`) subclasses `MasterPipelineRunner`. Decision at `:210-237`: `Settings.render_backend` (`core/settings.py:66`: auto|reference|stream); `auto` goes to the reference runner when profile is `cpu`, when the job is not "basic" (`:211-216`: execution_mode swap, lip sync off, no export/trim/face_segments/workstation_parameters/parameter_curves/mask, audio copy|drop, restoration policy in off|auto|gpen|codeformer|ultramax), when the media is VFR/rotated/start_time != 0 (`:224-229`), or when `NvdecFrameSource` validation raises ValueError (`:230-237`). `stream` + non-basic raises `STREAM_FEATURE_UNAVAILABLE`/`STREAM_TIMING_UNSUPPORTED` instead of falling back (`:220-221,226-229,236-237`).
- Reference path: `ReferencePipeline` (`engine/volumetric/session.py:90`) = FaceTracker (SCRFD + ArcFace + 106-pt) + `IdentitySwapper` + `LivePortraitAdapter` + `FrameCompositor` (+ optional restorer) + `LipSyncAdapter`; decode `VideoReader(hardware="auto")` (`engine/pipeline_runner.py:569`), encode `encode_video` (`:149,746`).
- Stream path: `Detector` + `FaceTracker(stabilize=False)` + `inswapper_128.batch.onnx` through `GpuBatchPipeline`/`CpuBatchPipeline` + optional `DecoupledRestorer` (`optimized_processor.py:256-287`); decode `NvdecFrameSource`, encode `NVHardwareVideoWriter` (`:46,109`). No BiSeNet/XSeg occlusion, no LivePortrait, no 3D modes in the stream path.

**F3. Zero Models are Stage 12 lifecycle READY in the shipped manifests, so no real-weight Engine can currently be constructed through `OrtModel`.** Evidence: (a) `models/governance.py:19-100` requires dependency state COMPATIBLE, security VERIFIED, non-empty `precision_requirements`, known license, etc.; every one of the 121 records has `dependency_compatibility.state=UNKNOWN`, `security_status=UNKNOWN`, empty `precision_requirements`, `benchmark_status=NOT_RUN`, `version_family=UNKNOWN` (script over `models/model_manifest.json`, `stage16_models.json`, `stage6_models.json` merged by `models/registry.py:151-172`). (b) Running the scanner over all 121 with `installed=True, integrity_verified=True` returned `LICENSE_RESTRICTED` x113 and `FAILED` x8 (the 7 candidates + 1 blocked), 0 `READY`. (c) `ModelCatalog.resolve_for_inference` (`models/catalog.py:131-142`), which `OrtModel.__init__` calls (`engine/runtime.py:113`), returned `LICENSE_UNVERIFIED` for every installed verified_local weight I probed (inswapper x2, scrfd/det_10g, w600k_r50, 2d106det, liveportrait x6 incl. landmark (appearance, landmark, motion, stitching, stitching_eye, warping_spade; `liveportrait_stitching_lip` has no record), gpen_bfr_512/1024, CodeFormerv0.1, codeformer.fp16, bisenet_resnet_34, xseg, xseg_3, face_occluder, hyperswap_1a, hififace_unofficial_256, GFPGANv1.4, restoreformer_plus_plus, 1k3d68). (d) `docs/STAGE12_MODEL_GOVERNANCE.md:70-74` states "the scanner reports zero models READY for inference"; `tests/model_governance_support.py:8-13` skips real-weight tests for that reason. (e) `LocalWeightProvider.open` and `ModelCatalog.verified_bytes` apply the same gate (`models/local_provider.py:88-95`; `models/catalog.py:90-99`), so `Detector`/`Recognizer` CPU fallback paths are gated too. The weights are physically installed (hash-verified `provider.resolve` succeeded for all verified_local ones; the four Stage 16 `verified_remote` ids probed (`bisenet_resnet_18`, `hififace_unofficial_256` (the remote id, distinct from the local `8a5bb0b5...` record of the same file), `xseg_1`, `xseg_2`) returned `MODEL_NOT_INSTALLED`). This is a fact about the working tree, not a claim about any other machine's manifests.

**F4. `ModelRecord` carries almost none of the fields the ticket asks for.** Across all 121 records: `minimum_vram_gib` None and `recommended_vram_gib` None (121/121); `supported_precision` empty and `precision_requirements` empty (121/121); `supported_providers` non-empty for 4 (all `("CPUExecutionProvider",)`: `df98ccc0...` scrfd_10g_bnkps, `caa04711...`/`de9199ff...`/`3f1189c4...` det_10g); `hardware_requirements` `{"state":"UNKNOWN"}` (121/121); `inference_availability` UNKNOWN x117, EXPERIMENTAL x4 (the Stage 6 LoRAs). Roles in use (`models/registry.py:17-21` vocabulary): verified_local counts: None 29, identity_swapper 15, face_restorer 13, detector 11, recognizer 9, occlusion_mask 6, liveportrait_stitch 4, face_parser 2, liveportrait_appearance/motion/warp 2 each. **There is no role for dense landmarks, video codec or 3D reconstruction**: the dense-landmark Models (`2d106det.onnx`, `liveportrait_landmark.onnx`, `1k3d68.onnx`) have `role=None`; the vocabulary entry `dense_mesh` and `flame_encoder`/`lip_sync`/`diffusion_*` have no verified_local record. 16 sha256 groups have more than one record id (e.g. sha `5838f7fe...` = 4 ids across `scrfd_10g_bnkps.onnx` and `det_10g.onnx`; `4c06341c...` = 3 ids w600k_r50; `f001b856...` = 3 ids 2d106det; `e4a3f08c...` = 2 ids inswapper_128; `48ccd7e8...` = 2 ids xseg_3).

**F5. ## 5. Exclusivity and residency hazards found in code

- **Per-job admission (12gb vs 6gb).** `VRAMGovernor.try_acquire`: 6gb -> capacity 1 GPU lease; 12gb -> capacity `min(max_concurrent_jobs, usable // 4096)`; fresh hardware probe each admission; CPU lease when no GPU / below reserve; `Settings.max_concurrent_jobs` default 1 (`engine/vram_governor.py:64-128`, `core/settings.py:55`). `RuntimeScheduler` wraps it (`engine/scheduler.py`).
- **No intra-job eviction.** `ReferencePipeline.prepare_session` constructs and holds sessions for tracker (detector, recognizer, 106-pt, 203-pt lazily), swapper, 4-5 LivePortrait Models, parser, up to 2 visible-face nets and one restorer until `release_session()` (`session.py:119-155,419-440`). The only eviction mechanisms are `AdaptiveModelPool` (unused in jobs, F9) and `engine/resources.py:evict_for_build` (releases every registered owner before a TensorRT compile and refuses if any ORT session or torch allocation survives, `:37-68`).
- **Process-wide fence.** `@guarded` methods share one `RLock` (`engine/resources.py:14-28`).
- **Preview vs owner gate.** `server/engine_gate.py:EngineGate`: previews never wait and are refused (`ENGINE_BUSY` 503) while any `gpu`-domain owner (render job, model rebind, TRT compile) holds or waits; owners wait for in-flight previews; `openvino` domain bypasses the GPU lock (`:40-126`).
- **OOM handling.** `is_cuda_oom` (`vram_governor.py:170-187`) -> one checkpointed CPU retry (`pipeline_runner.py:645-652,760-765`); a second failure is `PIPELINE_OOM`.
- **LivePortrait warp.** On CUDA it needs the converted derivative graph and carries the largest arena divisor (1/2); the receipt shows CPU as the only qualified provider for the original graph (F5).
- **TensorRT builds.** Workspace 1 GiB per build in the receipts; build requires evicting every registered owner first (`models/accelerated_runtime.py`, `models/trt_builder.py`).
- **Codec sessions.** No VRAM or lease accounting for NVDEC/NVENC; `CudaWorkerContext` only binds the CUDA primary context per thread (`render_policy.py:44-80`).
- **Heterogeneous scheduler.** `heterogeneous_scheduler.py` / `openvino_coprocessor.py` (Stage 15 domain `openvino`) have no production caller beyond the device probe (F8).
